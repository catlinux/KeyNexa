# Copias en la nube con asistente (ADR-0008)

Estado del ADR: **Propuesta** (2026-10-15). Orquesta Sonnet; implementa AgentRelay (una tarea por paso, árbol limpio al lanzar). Cada paso: `.\gradlew.bat check` y `bash scripts/check-docs-i18n.sh` en verde, VERSION + CHANGELOG en/es y documentación en los dos idiomas en el mismo commit; las tareas delegadas incluyen siempre las pruebas pedidas y la versión exacta. Antes de 1.0 una funcionalidad compatible sube la versión menor. Lecciones ya aprendidas con el ejecutor: sin E/S de red ni de almacenamiento en la composición, sin alias duplicados, sin registrar secretos, revisar siempre el diff y probar en el móvil.

Cuando el ADR-0008 se acepte, pasa a «Aceptada».

- [x] **H1. Variantes `offline` y `cloud`** · 0.16.0 · esfuerzo medio. Dimensión de sabor en `app-android` (`offline` por defecto, sin cambios de comportamiento; `cloud` declara `INTERNET`). La biblioteca `platform-android` declara la misma dimensión (mismo código en ambos sabores) para que el emparejamiento de variantes funcione. El módulo de red aún no existe: `cloud` solo cambia el manifiesto y el nombre de la variante en Ajustes/«Acerca de». Script o prueba que falle si el manifiesto fusionado de `offline` contiene `INTERNET`. CI compila y comprueba ambas variantes; el workflow de release firma y publica solo la `offline` (con el nombre actual `keynexa-X.apk`) hasta que la variante `cloud` tenga funciones (H5): un APK que pide Internet sin usarlo no se publica. Mismo `applicationId`, `versionCode` y firma. Las rutas de los APK cambian con los sabores (`app-android/build/outputs/apk/offline/...`); actualizar workflow, README y `docs/` que las citan, el borrador de F-Droid (`gradle:` con el sabor `offline`) y regenerar `app-android/gradle.lockfile` (y comprobar `gradle/verification-metadata.xml`) porque cambian los nombres de configuración. Si una variante se instala sobre otra no está verificado: documentarlo así. README, `docs/RELEASING` si existe, README de tiendas (`fastlane` describe `offline`), CHANGELOG.
- [x] **H2. Interfaz `CloudBackend` y subida de copias** · 0.17.0 · esfuerzo alto. Interfaz en `core-sync` (`put/get/list/delete` por nombre con etiqueta de entidad y marca `conditionalWrites`), `BackupUploader` (nombre `<bóveda>-<UTC>.kdbx` bajo un prefijo propio, rotación de las N últimas solo de lo creado por KeyNexa, límite de una subida al día, estado y último error, nunca bloquea el guardado) y un doble en memoria para pruebas JVM (rotación, fallo de subida, límite diario, no borra lo ajeno). Sin red todavía.
- [x] **H3. Backend S3** · 0.18.0 · esfuerzo alto. Cliente S3 en un módulo nuevo (`platform-cloud`) con el cliente HTTP de la plataforma detrás de una interfaz (`HttpsURLConnection`; justificar y registrar cualquier dependencia en `docs/DEPENDENCIES_AND_LICENSES.md` y `CREDITS.md`, en/es). Firma AWS SigV4 con `javax.crypto` (HMAC-SHA256 estándar, nada de criptografía propia) probada con los vectores oficiales; path-style y virtual-hosted, endpoint personalizado (B2, R2, MinIO), PUT/GET/LIST/DELETE. Pruebas con servidor HTTP local falso. Sin logs de URLs ni cabeceras.
- [x] **H4. Almacén de credenciales y pantalla de consentimiento** · 0.19.0 · esfuerzo alto. Credenciales cifradas con una clave no exportable del Keystore (AES-GCM) en `noBackupFilesDir`, borrado completo al desconectar; pantalla de consentimiento (qué se envía, a dónde, para qué; qué no sale nunca; cómo desconectarse) exigida antes de configurar; `docs/PRIVACY.md` en/es; THREAT_MODEL en/es con las amenazas nuevas.
